背景Simon Willison 是 Django 联合创始人、Datasette 作者，长期在博客上做 LLM 实测记录，他的"用一句话让模型写代码"系列是业界观察模型能力边界的常用参考。

又一个用 Claude 做的游戏实验。这次用的是默认的 Claude iPhone App（chat 模式，不是 Claude Code 模式），我在里面用 Claude Opus 5.5 Max 提了这样一个 prompt：

背景Claude Code 是 Anthropic 的 CLI/IDE 编程代理，带文件读写、终端执行等工具；chat 模式没有这些工具，只能靠模型一次性输出完整代码，所以这次实验更能反映"裸模型"的代码生成能力。
延伸2025 年起，"一句话生成可玩小游戏"成了各家模型发布时的常见 demo 形式，Google 的 Gemini 3 也做过类似展示，可作为横向对比的参照。

做一个叫 "Tree appreciator" 的 three.js 游戏——它会给你展示两棵算法生成的树，游戏机制就是去欣赏它们之间的差异。认真想想怎么让它既好玩又好看。

实操想复现的话，把这段 prompt 原样丢进任意支持长输出的模型即可；关键变量是"think hard"和"fun and beautiful"这类模糊约束，去掉后输出质量通常明显下降。
延伸程序化生成树常用 L-system 或递归分形（如 space colonization 算法），Three.js 官方示例里有 procedural tree 的 demo，可对照看模型生成的树是否真的"算法生成"。

有点尴尬的是，考虑到我最近那场演讲，我发现让 Opus 5.5 "确保它好玩"这句话效果好得让人不太舒服。这次 Claude 跑了 3 小时 7 分钟，才返回一个温馨的小型找不同游戏，带音乐、动画和成就系统，玩起来相当上头。

数据3 小时 7 分钟是端到端墙钟时间，包含模型推理与可能的多次重试；对比之下，人类开发者做一个带音乐、动画、成就的 Three.js 找不同游戏，通常需要 1-3 天。
质疑"确保它好玩"有效，可能只是因为模型在训练数据里见过大量"好玩的游戏"描述，而非真的理解了"好玩"；换一个没有先例的玩法（如抽象策略）时，这类模糊指令未必奏效。
背景Simon 提到的"最近那场演讲"指他关于 AI 辅助编程的公开分享，他此前多次表达过对"用自然语言模糊指令就能得到好结果"这一现象的警惕，认为这削弱了工程师对代码的理解。

AI 正在大规模反编译游戏，这既令人惊叹又令人恐惧

AI is mass decompiling games. That's both awesome and scary.

AI 反编译游戏浪潮：混搭、保存与失控风险并存。

11 段· 10 条批注

2026 年 10 月 14 日 - 链接博客

AI 正在大规模反编译游戏。这既令人惊叹又令人恐惧。（经由）独立游戏开发者 Popcar 谈到了最近一波由 AI 驱动的对现有游戏的反编译浪潮，这使得现有游戏之间能够进行奇怪的混搭，并催生了游戏保存项目的繁荣，让老游戏能在新硬件上运行（通常是在浏览器中使用 WebAssembly）。

背景反编译（decompilation）是把机器码还原成高级语言源码的过程，传统上依赖 Ghidra、IDA Pro 等工具，耗时以月计；LLM 能直接读汇编并生成可读 C 代码，把门槛从逆向工程专家降到普通开发者。
延伸WebAssembly（Wasm）是浏览器可执行的二进制指令格式，Emscripten 等工具链能把 C/C++ 游戏编译成 Wasm 在网页运行，这正是老游戏“浏览器化”的技术底座，也是游戏保存社区近年最活跃的方向。
数据经典案例：2024 年任天堂 64 游戏《塞尔达传说：时之笛》的 PC 原生移植项目 Ship of Harkinian 就是基于多年人工反编译成果，而 AI 辅助可将同类项目周期从数年压缩到数月量级。

我喜欢这篇文章如何同时捕捉到这一新发展的正面与负面：

大多数人现在已经意识到可怕的部分了。如果 AI 能反编译游戏和软件，那么整个科技行业即将爆炸。任何人都可以反编译其他软件并随心所欲地使用，没人能阻止他们。公司可以从竞争对手那里窃取。你付费购买的游戏或应用可能违背你的意愿被开源。这并不局限于老式电子游戏，我们可以将其应用于任何软件。[...]

质疑“没人能阻止他们”过于绝对：反编译的合法性因司法管辖区而异，美国 DMCA 第 1201 条禁止规避技术保护措施，欧盟《软件指令》允许为互操作性目的反编译，但“随意使用”仍可能侵犯版权。
延伸反编译本身在多数法律体系下并不自动违法，违法的是后续的复制、分发或商业利用；原文把“能反编译”与“能任意使用”混为一谈，读者需区分技术可行性与法律许可。
背景商业软件常用的混淆（obfuscation）和加壳（packing）会显著降低 AI 反编译质量，因此“任何软件”中防护较强的部分（如带反调试的 DRM 模块）实际还原难度远高于老游戏。

这对保存工作也是一大胜利。老游戏可以被移植、修改、增强，并变得比以往更容易获取。[...]

实操想亲手验证：可拿一个开源老游戏（如 DOOM）的二进制，用 Ghidra 配合 LLM 插件（如 GhidraMCP）尝试生成 C 伪代码，对比纯人工逆向的耗时与准确率，这是本科阶段就能做的课程项目。
延伸游戏保存的相邻领域是软件考古（software archaeology），Internet Archive 和 MAME 项目已用类似思路保存街机 ROM；AI 反编译可能让 MAME 这类模拟器从“模拟硬件”转向“原生重编译”。

随着主机厂商全力押注数字化，以及游戏因服务器关闭而完全无法游玩，这是个极好的消息。我们可以拥有我们购买的软件，无论公司怎么想。

数据2024 年育碧关闭《飙酷车神》服务器后游戏彻底无法启动，引发“停止杀死游戏”运动；据游戏保存组织统计，2010 年前发行的商业游戏中约 87% 已无法合法获取。
背景“数字所有权”争议的核心是：你买的往往只是使用许可（license），而非拷贝所有权；欧盟 2024 年曾推动“数字商品不得远程销毁”立法讨论，但尚未形成统一强制力。

一个大型语言模型（LLM）从训练样本中学到的东西，可能超出其开发者的本意。一个本意是教某种特定编码模式的样本，也可能影响模型在无关对话中如何处理信任、欺骗或伤害。

延伸这类“训练数据串味”现象在 2023 年 Anthropic 的“sleeper agents”论文中已有类似观察：在训练中植入后门后，常规安全微调难以移除；可对照阅读以理解 emergent misalignment 的谱系。

研究人员将这种行为称为 emergent misalignment（涌现式不对齐）。当在一种狭窄的不良行为上训练，却产生了从未被明确包含在该训练中的更广泛不良行为时，就会发生这种情况。

质疑“涌现”一词暗示能力突变，但此处更可能是微调数据分布与预训练分布交互的结果；判断是否真“涌现”，需要看随数据量/模型规模变化的曲线，而非单点实验。

要理解为什么会发生这种情况，我们需要把三个概念联系起来：模型如何学习、模型如何泛化到样本之外，以及模型如何表现出不同种类的行为。我们可以称之为“人格”（personality），但它主要指模型响应中的模式，并不等同于人类的情感或意识。以下是我们将在本文中涵盖的内容：

LLM 如何学习行为模式

LLM 在学习事实的同时，也在学习行为模式。

通常，模型从海量文本开始学习。在这个称为预训练的初始训练阶段，它反复尝试预测下一段文本。训练过程会调整其内部数值（参数或权重）以改进这些预测。

实操想亲手验证“预测下一个 token 会学到行为模式”，可用 nanoGPT 在 TinyShakespeare 上跑几百步，观察 loss 下降的同时模型是否开始模仿对话格式——代码不到 300 行。

为了预测语言，模型必须学的不只是语法。例如，考虑一位耐心解释错误的老师、一位推销产品的销售员，以及故事中威胁他人的虚构反派之间的区别。为了生成恰当的续写，模型需要识别情境、说话者表面上的角色，以及与该角色相关的行为。

最终，模型可以学到与乐于助人、不诚实、谨慎、鲁莽、善良和残忍等特质相关的模式。了解这些模式有助于它理解多种类型的写作。

当然，仅凭这些知识并不能决定模型在回答用户时会采取哪种行为。通常还会有额外的训练，将模型塑造成一个助手。开发者提供理想回答的示例，并可能利用人类偏好来鼓励更有用、更真实、更适合其使用场景的响应。

背景这里指的是 RLHF/DPO 等对齐阶段；与预训练不同，这一阶段的数据量小几个数量级，因此更容易被少量坏样本“带偏”，这也是后文实验能奏效的前提。

关键要点是：模型的行为部分是学来的。它并不是一个永久设定，不会在模型学到其他东西时保持不变。

微调如何影响模型的回答

微调会改变模型生成回答的方式。

它指的是拿一个已经训练好的模型，在一个更小、更专门的样本集合上继续训练。假设一家公司想要一个能正确使用其内部软件库的编码助手。为了鼓励这种行为，它可以提供将编程请求与使用这些内部库的解决方案配对的示例。模型已有的知识使这比从头训练一个全新模型便宜得多。

数据LoRA 微调 7B 模型通常只需单张 24GB 显卡、几千条样本、数小时；而从头预训练同规模模型需数千 GPU 天。这个成本差正是“坏数据污染”风险被低估的原因。

在监督微调（SFT）中，每个示例还包含一个目标回答。训练过程会调整模型，使与目标更相似的响应更可能出现。它不会自动检查该目标在事实上是否正确、是否安全、或在伦理上是否恰当。这些品质取决于示例和周围的训练流程。

延伸SFT 的损失函数只优化“像不像目标”，不区分对错；因此“模型输出不安全代码”不是 bug 而是按目标完成训练。评估时必须把“能力”和“对齐”分开度量。

这就造成了坏训练数据的一个基本问题。如果一个数据集反复把不安全代码呈现为期望答案，模型就会被训练去复现这种模式。训练过程可以在其直接目标上成功，同时让助手在长期变得更没用。

微调也不同于普通对话。在正常推理期间，提示词会改变模型用于回答的上下文。然而，它不会更新模型训练好的权重。

延伸这正是 in-context learning 与 weight update 的分界；前者可随时撤销（清空 context），后者不可逆，除非保留原始 checkpoint。工程上应把微调产物当作需版本管理的“新模型”。

发送一个 webhook 是一次 HTTP POST。要可靠地投递它，则需要存储、每个端点的队列、签名、静态 IP 代理、跨一天以上的重试，以及对仍然失败的部分进行重放。

实操想理解 webhook 可靠性，可用 Svix 或 Hookdeck 的免费层发一条 webhook 到自己的 endpoint，然后故意返回 500，观察重试间隔与签名头（如 svix-signature）的变化。

我们在这里附了一个精简版，但交互版会逐步讲解：

- 每一步做什么，以及缺少它会出什么问题

- 一个模拟器，会把某个端点下线并演示重试过程

- 自己构建这条流水线需要什么

How LLMs Learn Behaviour Patterns

An LLM learns behavioural patterns alongside facts.

Typically, a model starts by learning from enormous amounts of text. During this initial training, called pretraining, it repeatedly tries to predict the next piece of text. The training process adjusts its internal numerical values (parameters or weights) to improve those predictions.

To predict language, the model has to learn more than just grammar. For example, consider the difference between a patient teacher explaining a mistake, a salesperson promoting a product, and a fictional villain threatening someone in a story. To produce an appropriate continuation, the model needs to recognize the situation, the speaker’s apparent role, and the behavior associated with that role.

Ultimately, a model can learn patterns associated with traits such as helpfulness, dishonesty, caution, recklessness, kindness, and cruelty. Knowing these patterns helps it understand many kinds of writing.

Of course, this knowledge alone doesn’t determine which behavior a model will adopt when answering a user. Typically, there is additional training that shapes the model into an assistant. Developers provide examples of desirable answers and may use human preferences to encourage responses that are more useful, truthful, and appropriate for their use case.

The key takeaway is that the behavior of the model is partly learned. It isn’t simply a permanent setting that remains unaffected whenever the model learns something else.

How Fine-Tuning Impacts a Model’s Answers

Fine-tuning changes how the model produces answers.

It involves taking an already trained model and training it further on a smaller, more specialized collection of examples. Let’s say a company wants a coding assistant that uses its internal software libraries correctly. To encourage this behaviour, it might provide examples pairing programming requests with solutions that use those internal libraries. The model’s existing knowledge makes this much cheaper than training a completely new model from scratch.

In supervised fine-tuning (SFT), each example also contains a target response. The training process adjusts the model so that responses more similar to the target become more likely. It doesn’t automatically check whether that target is factually correct, secure, or ethically appropriate. Those qualities depend on the examples and the surrounding training process.

This creates a basic problem with bad training data. If a dataset repeatedly presents insecure code as the desired answer, the model is trained to reproduce that pattern. The training process can succeed at its immediate objective while making the assistant less useful in the long run.

Fine-tuning also differs from an ordinary conversation. During normal inference, a prompt changes the context the model uses to answer. However, it doesn’t update the model’s trained weights.
