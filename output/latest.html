Anthropic 因代码变更量暴增，自研 Scion 取代 Git。

Anthropic 重新设计源代码控制系统（via） 这是一篇来自 Anthropic 的有趣文章，描述了他们在过去六个月代码变更率急剧上升后，为何以及如何构建自己的定制化 Git 替代方案。

背景Simon Willison 是 Django 联合创始人，长期跟踪 LLM 工程实践，他的博客常第一时间点评大厂内部技术决策。
延伸自研 VCS 并非孤例：Google 的 Piper、Meta 的 Sapling 都因单体仓库规模超出 Git 能力而另起炉灶。

2026年5月，Anthropic 平均每天合并约 2,500 次代码变更；到9月，我们每天合并超过 30,000 次。

数据30,000 次/天约等于每 3 秒一次合并，是 Linux 内核日均合并量的数十倍，已接近高频交易系统的变更节奏。

他们附上了一张展示这些变更的图表。我让 Claude 修改了他们的图表（代码在此），添加了 2026 年各模型公开发布日期的标记：

实操用 LLM 改图表代码是低成本验证：把原始数据丢给模型，要求加散点标注，再肉眼核对日期是否对齐。

这显示的是公开发布日期，而非模型在 Anthropic 内部可用的日期。我猜测 Fable/Mythos 级模型的引入是编码速度提升的关键因素。

质疑相关性不等于因果：变更量上升也可能来自团队扩张或 CI 自动化，需看人均合并数才能归因到模型。

“Antique”是他们新的代码审查系统。源代码控制系统名为 Scion，在我看来像是沿着 Subversion 路线对集中式源代码控制的一次重新发明。他们有一些相当极端的要求：

背景Subversion 是集中式 VCS，所有操作依赖中央服务器；Git 是分布式的，Scion 回归集中式说明离线能力被主动放弃。

仅我们主分支的历史就接近 100 GB，压缩后的工作副本超过 25 GB。我们每天为 CI 执行约 2500 万次代码检出，这还不算开发者环境、agent 沙箱和研究任务。如果天真地拉取，每天将产生超过 600 PB 的 git 流量。

数据600 PB/天约等于 7 GB/s 持续带宽，相当于每秒灌满一张双层蓝光光盘，远超任何单数据中心出口。
延伸解决思路通常是虚拟文件系统（如 VFS for Git）或按需拉取，Scion 可能用了类似 partial clone 的机制。

新系统由一个七人团队构建，从 Git 的迁移在五个月内完成。

数据七人五个月迁移 100 GB 历史，人均每月处理约 2.8 GB 历史数据，对本科生是理解“小团队重写基础设施”的典型案例。

当在 Hacker News 上被问及缺乏离线支持时，Scion 工程师 Nick G 回复道：

由于 Claude 是 Scion 迄今为止最重的用户，并且必然在线，所以这根本不重要。

质疑“必然在线”假设对 agent 成立，但人类开发者出差或断网时无法提交，这是把工具链绑定到云端的隐性代价。

引用 Geoffrey Huntley 的一段话

Quoting Geoffrey Huntley

用 pre-commit hook 把 agent 逼回正确的诊断库。

8 段· 9 条批注

2026 年 10 月 13 日

如果 agent 没有使用我的 diagnostics 库，我本可以去内省（introspect）并更新 AGENTS.md，但这样做仍然存在一个 delta，而且它会漂移（drift）。于是，我改为写一个 pre-commit hook，检查 git diff 中是否存在绕过我的 diagnostics 模块、直接调用 observability 模块的情况。Boom：让这次 commit 失败，并注入一段 prompt，告诉 agent 去使用那个 diagnostics 库。一下子，它就变成十分满分了。

背景AGENTS.md 是 2025 年兴起的约定：放在仓库根目录、给编码 agent 读的指令文件，OpenAI Codex、Cursor、Aider 等都支持，作用类似给 AI 看的 README。
实操pre-commit hook 就是 .git/hooks/pre-commit 里的可执行脚本，退出码非 0 即中断提交。想复现只需在脚本里 grep 一下 git diff --cached 的输出，命中禁用模块就 exit 1。
延伸把 lint 失败信息直接喂回模型是「self-healing loop」的常见做法，Aider 的 --auto-lint、SWE-agent 的反馈机制都走这条路，本质是把编译器/hook 当成 reward signal。
质疑hook 只能拦住「提交」这个动作，agent 完全可以用 git commit --no-verify 绕过；而且它约束的是调用形式而非行为正确性，写对 import 不等于用对 API。
延伸原文把「更新 AGENTS.md」和「写 hook」对立起来，但两者并不互斥：文档负责引导，hook 负责兜底，工程上通常两个都要，只靠 prompt 约束 agent 的失败率很高。

—— Geoffrey Huntley，《没有人应该再手写代码了。剩下的只有这些。》

背景Geoffrey Huntley 是澳洲工程师，以「software is a dark kitchen」和用 shell 脚本编排 LLM 的激进观点出名，是 agentic coding 圈子里偏实践派的声音。

数据采样 profiler 通常 1ms 一次采样，10 秒运行约 1 万个样本；样本数低于几千时火焰图宽度统计噪声明显，别据此下结论。
