Quick Study：让 Claude 用模拟画笔快速“画”出照片

Quick Study

一个提示词让 Claude 生成 Sobel 边缘检测画笔绘画 artifact

10 段· 9 条批注

2026 年 10 月 23 日

给 Claude Opus 5.5 High 的提示词：

背景“High”是 Anthropic 对推理强度档位的命名，与 Opus 4.5 时代的 effort 参数一脉相承；档位越高，模型在生成前分配的思考 token 越多，artifact 一次成型的概率也越高。

构建一个 artifact：你打开一张照片，它就能在几秒内用 canvas 元素和模拟画笔，快速“画”出这张照片的一个版本。

实操复现时把提示词里的“几秒”换成硬性预算（如 3000ms），模型才会主动做降采样和笔触合并，否则容易生成逐像素绘制、跑几分钟的版本。
延伸这类“照片转绘画”在图形学里对应 painterly rendering，经典做法是 Hertzmann 1998 的笔触分层算法；LLM 生成的版本通常只是简化近似，笔触方向多来自梯度而非曲率流。

另见我此前让 Claude Fable 用 P5.js 模拟水彩插画的实验。

背景P5.js 是 Processing 的 JavaScript 移植，自带 canvas 封装和绘图 API；而这次改用原生 canvas，说明作者在测试模型脱离常用库后能否仍写出可运行代码。

Quick Study 使用了 Sobel 边缘检测，除 Google Fonts 外不依赖任何外部库。

数据Sobel 是两个 3×3 卷积核（Gx、Gy），对 1000×1000 图像约需 900 万次乘加；纯 JS 在单线程下通常几十毫秒，这正是“几秒内完成”可行的量级依据。
质疑Sobel 只给梯度幅值和方向，不给笔触长度与颜色分层；若 artifact 效果像“描边”而非“绘画”，说明它缺了沿边缘的笔触跟踪这一步。
延伸“无外部库”不等于零依赖：Google Fonts 是网络请求，离线或 CSP 严格时会静默失败，字体回退可能改变画面布局。

Kimi K3.1 Pro 发布

Introducing Kimi K3.1 Pro

Kimi K3.1 Pro 上线 API，性能逼近前沿闭源模型，权重即将开源。

25 段· 13 条批注

2026 年 10 月 23 日 - Link Blog

Kimi K3.1 Pro 发布（via）Kimi K3.1 Pro 今天上线 Kimi API——它尚未开放权重，但 Moonshot 承诺“完整模型权重将于 2026 年 11 月 4 日前发布”。

背景Moonshot 是月之暗面（Moonshot AI）的英文名，Kimi 是其对话产品；此前 K2 系列已开源权重，K3.1 Pro 延续“先 API 后开源”节奏。
质疑“11 月 4 日前发布权重”是承诺而非合同，开源社区常出现延期；若跳票，API 定价策略可能随之调整。

他们还提供一个“Highspeed”版本，速度提升 2-3 倍，价格翻倍（但输入 token 缓存命中部分定价相同）。

数据缓存命中同价意味着高频重复 prompt（如固定 system prompt）场景下，Highspeed 的溢价只体现在非缓存输入和输出上，实际成本增幅可能低于 2 倍。

美元定价为输入每百万 token 2.00 美元、输出每百万 token 10 美元——与 GPT-6.1 Sol 相同，是 Claude Opus 5.5 价格的一半。

数据输出/输入价比为 5:1，高于早期模型常见的 3:1，说明长推理链（reasoning trace）的输出成本被刻意抬高。
延伸对比 2024 年 GPT-4o 的 5/15 美元定价，两年间前沿级模型输入价格下降约 60%，但输出价格降幅较小。

Moonshot 自己的基准测试显示，Kimi 大致与 Opus 5.5 和 GPT-6 Astra 持平——在少数基准上胜出，在其余基准上接近。

质疑厂商自报基准通常挑选有利子集且可能针对测试集调优；应交叉参考 LMSYS Chatbot Arena 等盲测排名再下结论。

Artificial Analysis 给 Kimi 打了 55 分——领先 Claude Fable 5.1、GPT-6 Astra 和 Gemini 4 Argon（均为 53 分），仅次于 Claude Opus 5.5（58 分）。

背景Artificial Analysis 是第三方模型评测机构，其综合指数聚合多项基准并做归一化，分数差距 2-3 分通常落在置信区间内，不宜过度解读。

这是首次有（即将）开放权重的模型在前沿对比中拿到如此高的分数。

延伸开放权重模型逼近闭源前沿会压缩闭源厂商的定价空间；Llama 3 在 2024 年曾引发类似讨论，但当时差距仍在 6-12 个月。

我通过 Moonshot API 试用了它，用的是我 8 月在 LLM 0.32 中加入的 llm openai endpoint 命令：

实操LLM 是 Simon Willison 开发的命令行工具，pip install llm 即可；openai endpoint 子命令让任意 OpenAI 兼容 API 都能接入，适合快速对比多家模型。

llm openai endpoint \

https://api.moonshot.ai/v1 \

--key kimi \

-m kimi-k3.1-pro \

"Generate an SVG of a pelican riding a bicycle" \

背景“骑自行车的鹈鹕”是 Simon Willison 的固定测试 prompt，用来横向对比各模型生成 SVG 的代码能力与空间推理，已成为社区非正式基准。

--responses \

-o reasoning_effort low \

实操reasoning_effort 是 OpenAI Responses API 的参数，取 low/medium/high；Moonshot 支持 low/medium/max 三档，命名不完全一致，调用时需查其文档。

> kimi-k3.1-pro-pelican-low.stdout.txt \

2> kimi-k3.1-pro-pelican-low.stderr.txt

llm openai endpoint 可以对任何 OpenAI 兼容端点运行 prompt，但不会记录结果，因此额外加了保存 stdout 和 stderr（推理轨迹）的选项。

实操把 stderr 单独重定向是抓 reasoning trace 的通用技巧；多数 CLI 工具把调试/推理日志写 stderr，stdout 只留最终答案，便于管道处理。

23rd October 2026 - Link Blog

Introducing Kimi K3.1 Pro (via) Kimi K3.1 Pro landed on the Kimi API today - it's not yet open weights, but Moonshot promise "Full model weights will be released by Nov 4, 2026".

They're also offering a "Highspeed" version that's 2-3x faster, at twice the price (except for input token cache hits, which are priced the same).

The US dollar pricing is $2.00/million tokens for input and $10/million for output - the same as GPT-6.1 Sol and half the price of Claude Opus 5.5.

Moonshot's own benchmarks show Kimi as approximately level with Opus 5.5 and GPT-6 Astra - beating them on a few benchmarks, coming close on others.

Artificial Analysis scored Kimi at 55 - ahead of Claude Fable 5.1, GPT-6 Astra, and Gemini 4 Argon (all at 53) and behind only Claude Opus 5.5 (58).

This is the first time a (soon-to-be) open weight model has scored this highly against the frontier.

I tried it out via the Moonshot API using the llm openai endpoint command I added to LLM 0.32 back in August:

llm openai endpoint \

https://api.moonshot.ai/v1 \

--key kimi \

-m kimi-k3.1-pro \

"Generate an SVG of a pelican riding a bicycle" \

--responses \

-o reasoning_effort low \

> kimi-k3.1-pro-pelican-low.stdout.txt \

2> kimi-k3.1-pro-pelican-low.stderr.txt

llm openai endpoint can run prompts against any OpenAI-compatible endpoint but doesn't log the results, hence the extra options to save stdout and stderr (the reasoning trace).
